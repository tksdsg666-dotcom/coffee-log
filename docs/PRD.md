# 咖啡记录 App — 产品需求文档 (v1)

## 1. 一句话

一个纯本地的个人咖啡日志，记录在家冲的每一杯（意式 / 手冲 / 冷萃）和在外喝的每一杯，
目的是回答一个问题：**这包豆子调到什么参数最好喝。**

## 2. 用户与场景

单一用户（开发者自己）。三个高频场景：

1. **早上冲一杯意式** → 记：豆子、粉量、液重、时间、研磨度、评分、一句话
2. **周末手冲** → 记：豆子、粉量、水量、水温、时间、研磨度、评分、一句话
3. **在外喝一杯** → 记：店名、品项、价格、评分、一句话（参数通常全空）

冷萃场景低频但存在，参数是粉量 / 水量 / 浸泡时长。

## 3. 一阶段范围

### 做

- 豆子的增删改查
- 咖啡记录的增删改查（在家 / 在外共用一个表单，靠有没有填店名区分）
- 时间线（首页）
- 豆子详情页：这包豆子的所有记录 + 参数演进
- 全部数据手动录入
- 数据导出为 JSON

### 明确不做（一阶段）

以下功能被有意排除，实现时不要主动添加：

- ❌ **冲煮计时器**（二阶段。一阶段时长手动填数字）
- ❌ **蓝牙电子秤**（二阶段。引入 `react-native-ble-plx` 会破坏 Expo Go 调试循环）
- ❌ 用户账号、登录、云同步
- ❌ 后端服务
- ❌ SCA 风味轮 / 多维度打分（只有 1–5 星 + 自由文本）
- ❌ 社交、分享、社区
- ❌ 推送通知
- ❌ 深色模式适配（先做浅色，跑通再说）
- ❌ 国际化（只有中文）
- ❌ 咖啡店数据库 / 地图 / POI（店名是自由文本 + 历史自动补全）
- ❌ 设备管理表（研磨度直接写文本，如「C40 22格」）

## 4. 数据模型

见 `schema.ts`（Drizzle）。要点：

- 两张表：`beans`、`logs`
- `logs.place` 为空 = 在家，有值 = 店名
- `logs.method` 是 `espresso | pourover | coldbrew | other`，在家和在外共用
- 六个可空数字列覆盖三种做法：`doseG` `yieldG` `waterG` `tempC` `timeS` `grind`
- **所有比例（粉水比、萃取比）都是算出来的，不入库**
- 研磨度是文本，不是数字

## 5. 页面

### 5.1 首页 / 时间线

- 按 `drankAt` 倒序的卡片列表
- 每张卡片：做法图标、豆子名或「店名 · 品项」、关键参数一行摘要、星级、日期
  - 意式摘要：`18g → 36g · 28s · 1:2.0`
  - 手冲摘要：`15g / 250g · 92°C · 2:30 · 1:16.7`
  - 在外摘要：`Manner · 燕麦拿铁 · ¥25`
- 右下角悬浮 + 按钮 → 新建记录
- 空状态：引导先去加一包豆子

### 5.2 新建 / 编辑记录

**这是全 App 最重要的页面，也是唯一值得反复打磨的页面。**

表单结构：

1. **第一步：在家还是在外**（分段控件）
   - 这个选择决定下面显示哪些字段，不要两套都渲染出来再隐藏
2. **做法**（分段控件：意式 / 手冲 / 冷萃 / 其他）
   - 参数字段根据做法变化：
     - 意式：粉量、液重、时间、研磨度
     - 手冲：粉量、水量、水温、时间、研磨度
     - 冷萃：粉量、水量、时间、研磨度
     - 其他：不显示参数
3. **在家** → 豆子选择器（只列 `isFinished = false` 的豆子，按最近使用排序）
   **在外** → 店名（自由文本 + 历史自动补全）、品项、价格
4. **参数区**（见上）
   - 意式填了粉量和液重 → 实时显示萃取比 `1:2.0`
   - 手冲/冷萃填了粉量和水量 → 实时显示粉水比 `1:16.7`
5. **评分**：1–5 星，可不填
6. **备注**：多行文本
7. **时间**：默认现在，可改

关键交互要求：

- **默认值来自上一条同做法的记录。** 每天冲意式参数差不多，不该每次从零填。
- 数字输入用 `keyboardType="decimal-pad"`
- 时间用秒填（意式 28，手冲 150），显示时格式化成 `2:30`
- 冷萃时长可能是 16 小时，输入时提供「小时」单位切换，入库仍存秒
- 保存后回到时间线，不弹确认框

### 5.3 豆子列表

- 分两组：在喝的 / 已喝完
- 每张卡片：名称、烘焙商、烘焙度、养豆天数、已记录杯数
- 右下角 + → 新建豆子

### 5.4 豆子详情

- 顶部：豆子信息、养豆天数、总杯数、平均分、每杯成本（`priceCny / 杯数`）
- **参数演进**：这包豆子的所有记录，按时间正序，表格形式一行一条：
  `日期 | 研磨度 | 粉量 | 液重/水量 | 比例 | 时间 | 评分`
  这张表是整个 App 的核心价值，比任何图表都重要，优先做好
- 「标记为已喝完」按钮

### 5.5 设置

- 导出全部数据为 JSON（`expo-file-system` + `expo-sharing`）
- 数据统计：总杯数、在家 vs 在外占比、各做法占比
- 危险区：清空所有数据（二次确认）

## 6. 技术约定

- Expo (SDK 最新稳定版) + TypeScript (strict)
- Expo Router，file-based routing，底部 Tab：时间线 / 豆子 / 设置
- expo-sqlite + Drizzle ORM + drizzle-kit 迁移
- 启动时用 `useMigrations` 跑迁移，迁移期间显示 loading
- 状态管理：不引入 Redux/Zustand。Drizzle 的 `useLiveQuery` 直接订阅数据库
- 样式：StyleSheet，不引入 UI 库
- 图标：`@expo/vector-icons`
- 所有金额单位人民币，所有重量单位克，所有温度摄氏度

## 7. 验收标准

一阶段完成的定义：

1. 能加一包豆子，填烘焙日期
2. 能记一杯意式，参数完整，比例实时计算正确
3. 能记一杯手冲，字段和意式不同
4. 能记一杯在外喝的，参数全空也能保存
5. 时间线正确倒序显示三种记录，摘要格式正确
6. 豆子详情页能看到这包豆子的参数演进表
7. 第二次记录时，参数默认值来自上一条同做法记录
8. 关掉 App 重开，数据还在
9. 能导出 JSON

## 8. 二阶段候选（不要现在做）

- 冲煮计时器（用时间戳差值实现，不用 setInterval 累加）
- 蓝牙电子秤（需要 expo-dev-client）
- 参数演进图表
- 照片
- 深色模式
- 数据导入 / 备份恢复
