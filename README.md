# 咖啡记录

一个纯本地的个人咖啡日志。Expo SDK 54 + React Native，数据全在手机上的 SQLite 里，没有账号、没有后端、没有同步。

界面和交互照 [`docs/design/SPEC.md`](docs/design/SPEC.md) 实现，设计 token 来自同目录下的 Organic 设计系统。

> **接手这个项目？先读 [`docs/HANDOFF.md`](docs/HANDOFF.md)** —— 这个 App 做什么、当前进度、下一步方向。

---

## 跑起来

手机装 [Expo Go](https://expo.dev/go)，和这台电脑连同一个 Wi-Fi，然后：

```bash
npm start
```

扫终端里的二维码。**不需要任何账号。**

同一网段连不上时（公司网络常见）走隧道，慢一些但能通：

```bash
npm run tunnel
```

其他命令：

```bash
npm test          # 领域逻辑单测（比例 / 研磨钳制 / 参数串 / 日期分组 / 5 星对比）
npm run typecheck # tsc --noEmit
npm run db:generate  # 改了 src/db/schema.ts 之后重新生成迁移
```

> `.npmrc` 把 registry 指向 npmjs.org，覆盖掉了全局那个内网源。别删。
>
> **项目锁在 Expo SDK 54**，因为设备上的 Expo Go 是 54.0.2——Expo Go 的版本号跟 SDK 走，只能加载同版本的项目。哪天 Expo Go 能更新到更高版本了，再整体升 SDK；升级时 `expo-sharing` 要重新加回 `app.json` 的 plugins（SDK 54 的它没有 config plugin），`Sheet.tsx` 里手写的 absoluteFill 可以换回 `StyleSheet.absoluteFill`。

## 这一轮做了什么

**做了**

- 数据层：`records` / `beans` / `brands` / `devices` / `settings` 五张表，Drizzle + expo-sqlite，启动时跑迁移
- **时间线**：按天分组、卡片、参数串、照片缩略图、删除
- **记一杯**：SPEC 规定的 11 步字段顺序、来源切换的清空副作用、五套参数配置、研磨卡片、实时比例、照片（拍照 / 相册）、三列滚轮时间选择、选豆子 sheet（含内联新建）、品牌 chips（含新建）
- **记录详情 + 编辑**：编辑复用记一杯表单
- **豆子**：两段列表（带杯数和均分）+ 新建
- **豆子详情**：三宫格（杯数 / 平均评分 / 高分常用比例）· 图标颜色 · 属性表 · **5 星并列对比** · 全部记录 · 编辑 · 删除（连带记录，行内二次确认）
- **我的**：设备管理（磨豆机带步长 / 量程 / 单位）+ JSON 导出 / 导入 / 清空
- **统计**（从「我的」进入）：月历（每天一个圆点，喝得越多颜色越深）· 本月杯数 / 喝了几天 / 最长连续 · 各做法圆点矩阵

**没做（下一轮）**

本月摘要 · 常喝品牌 · 品牌详情 · 搜索筛选 · 首次使用引导

时间线卡片上的**品牌标签**这一轮不可点——品牌详情还不存在，与其留死链接不如先不做成可点的。豆子名可点，进豆子详情。

## 相对 SPEC 的几处偏离

都是有意的，理由写在这儿而不是埋在代码里：

1. **加了记录编辑。** SPEC 的记录详情只有删除。真用起来记错一个数字只能删了重记，所以详情页右上角加了「编辑」，复用记一杯表单。
2. **导出是真的。** SPEC 里「我的 → 偏好 → 导出 CSV」是个静态行。这里做成了完整 JSON 备份（四张表全量）+ 导入 + 清空。照片按文件名引用，不塞进 JSON——一个月的照片 base64 进去会撑爆分享面板。导入时已存在的 id 跳过，不覆盖。
3. **评分默认留空。** 原型初始值是 4 星，意味着没评分的杯子也会存成 4 星。SPEC 的数据模型写的是 `r int? 可空`，所以这里默认不填，点星才有分，再点同一颗清空。
4. **研磨刻度 0 不再消失。** 原型用 `if (rec.grind)` 判断，刻度为 0 时整行不显示。这里判的是 `!= null`，有测试锁着。
5. **做法配色搬到了 `src/theme.ts`。** 这样 `src/domain/methods.ts` 不依赖 React Native，能脱离渲染器跑单测。
6. **没有浓缩这个做法。** 按 SPEC 原样五项。真要记浓缩就选「美式」把加水填 0。
7. **参数改成「± 加长按 + 点数字输入」，只有研磨保留滑条。** SPEC 写的是「点数字清空」，但那样没法直接跳到某个值——冷萃粉量从 10g 到 60g 要按十下 ＋。现在点数字弹数字键盘直接输，**清空改成把输入框清空**，「全部留空」照旧清整组。给每个参数都配滑条试过一版，页面太挤，只有研磨值得占那个高度（它的量程是磨豆机定的真实刻度）。
8. **门店优先的排序。** 实际使用里买的比自己冲的多，所以顺序按真实频率排：记一杯选「门店」时**品牌块提到来源下面第一位**（SPEC 里是第 8 步，但买咖啡时最先知道的就是店名）；豆子 Tab 和选豆子 sheet 都是**门店豆子在前**；选豆子按**最近 30 天频次**倒序，豆子 Tab 按**最近喝过**倒序；在记一杯里新建豆子，归属默认跟当前来源走。排序逻辑在 [`src/domain/beanOrder.ts`](src/domain/beanOrder.ts)，有测试。
9. **特调和其他拆开，特调带基底。** 原本是一个「特调 & 其他」。但特调有值得记的参数，纯粹归不了类的一杯没有，合在一起总有一边是错的。特调现在带一个**基底**（浓缩 / 冷萃 / 滴滤），参数表跟基底走——同一杯特调在这家店用浓缩、在那家店用冷萃甚至冰滴，参数完全不同。其他不显示任何参数。挂耳不单列，归到滴滤。做法从 5 个变 6 个，做法配色重新搜过一遍（六色最小色差 ΔE 18.9）。
10. **默认来源可以设置。** 「我的 → 偏好 → 默认来源」。它同时决定记一杯落在哪一边、豆子 Tab 哪一段在前、选豆子 sheet 的分组顺序。存在 `settings` 表里（不是设备存储），所以会跟着 JSON 备份一起走。
11. **关掉了 expo-router 的 typedRoutes。** 它的生成器在 Windows 上会把 `src/` 下的文件当成路由塞进类型里（`getWatchHandler` 用 `path.relative(...).startsWith('../')` 判断文件是否在 `app/` 外，而 Windows 上返回的是反斜杠），结果是**对正确的导航代码报假错**。改用手写的 [`src/lib/routes.ts`](src/lib/routes.ts)——6 条路由，手写反而更准。以后 SDK 修了就把 `app.json` 里的 `experiments.typedRoutes` 加回去。

## 数据会不会丢

没有后端。数据全在手机本地：`Documents/SQLite/coffee-log.db`，照片在 `Documents/photos/`。

| 场景 | 数据 |
| --- | --- |
| 改表结构后重新加载 / 重装安装包 | 保留 |
| 独立包升级到新版本（同 bundle id、同签名） | 保留 |
| 换手机，从 iCloud / 电脑备份恢复 | 保留 |
| **从 Expo Go 换成独立安装包（EAS Build）** | **丢** |
| 删除 Expo Go / 删除 App | 丢 |

### 加字段的正确流程

改 `src/db/schema.ts` → `npm run db:generate` → 重新加载。

Drizzle 在库里维护 `__drizzle_migrations` 表，启动时拿最后一条已应用迁移的 `created_at` 和 `_journal.json` 里每个迁移的 `when` 比较，**只跑时间戳更晚的**。老数据不动。

### 三条铁律

**1. 永远不要删掉 `src/db/migrations/` 重新生成。**

生成的 SQL 是 `CREATE TABLE`，没有 `IF NOT EXISTS`；迁移器只比时间戳，不比内容。重新生成会得到更晚的时间戳，装了旧版的手机上会重跑 `CREATE TABLE`，报 `table already exists`，App 起不来。只能往上加 `0001`、`0002`。

**2. 已经发出去的迁移文件不要改内容。** 改了对已安装的机器毫无作用（那条迁移不会重跑），只会让新旧设备的库结构不一致。

**3. 从 Expo Go 转独立包之前，先「我的 → 导出备份」。**

那是另一个沙盒，一条记录都不会跟过去。装好新包后用「从备份导入」恢复。完整 JSON 导出/导入就是为这一刻准备的。

### 迁移失败了怎么办

启动时迁移出错，App 会停在「数据库没能启动」那一屏，**不会清库**。那一屏上有个「抢救导出」按钮：它按表逐个读，某张表坏了就跳过并记进备份的 `unreadable` 字段，把还读得出来的全部导出去。

所以顺序是：**先抢救导出 → 再修迁移 → 修好前不要删 App**。删 App 才是唯一真正销毁数据的操作。

那一屏刻意不用 Caprasimo / Figtree——字体加载失败也是会落到这一屏的错误之一，它必须在没有字体的情况下也能显示。

### 照片为什么只存文件名

`records.photo` 存的是文件名，不是绝对路径。iOS 的应用沙盒目录带一个 UUID，**升级后会变**——存绝对路径的话升级完所有照片全部失效。渲染时才用当前的 `Paths.document` 拼出来（见 [`src/lib/photos.ts`](src/lib/photos.ts)）。

## 三个关键约束，改代码前先看

**数字必须用 `<Num>`，中文必须用 `<Txt>`。** Caprasimo 没有中文字形，中文用它会静默回退到系统字体并丢掉字重。「所有数字用 Caprasimo」是这套设计的主要视觉特征。

**导航一律走 `routes.*`，不要手写路径字符串。** 理由见上面第 11 条。

**研磨刻度永远跟着磨豆机走。** 量程、步长、单位都来自 `devices` 表，记录里存了一份 `gunit` 快照——所以换磨或删磨之后，老记录仍然按自己的单位显示。任何读写研磨值的地方都要过 `clampGrind`。
